\subsection{Audio Deepfake Detection Service}

\begin{figure}[H]
    \vspace{1em}
    \centering
    \includegraphics[width=1\textwidth]{images/methodology/detection_service.png}
    \vspace{0.25cm}
    \caption{Audio Deepfake Detection Service}
    \label{fig:detection_service}
\end{figure}

The audio deepfake detection service is the core inference component of the proposed system. It receives reconstructed receiver-side audio and performs analysis to determine whether the speech segment is real or synthetic. In contrast to tightly coupled end-to-end RTC implementations, the proposed design isolates deepfake detection as an independent service that can be integrated into different RTC/VoIP platforms through a standard API layer.

This service operates on short streaming windows rather than complete utterances, which makes it suitable for real-time deployment. Its output is a probabilistic decision that can be consumed by the RTC application for alert generation, monitoring, or downstream security enforcement.

\subsubsection{Service Architecture}

The detection module is implemented as a stateless inference service exposed through gRPC or HTTP APIs. This architecture allows the RTC system to send continuous stream to the detector without requiring modifications to the core communication stack.

Let the reconstructed receiver-side audio be denoted as $x_{out}[n]$.

The RTC client or receiver component forwards successive audio chunks to the detection service, which processes each chunk independently while preserving limited contextual information for temporal stability. The service can therefore be deployed in different environments, including:
\begin{itemize}
    \item centralized cloud servers,
    \item edge nodes close to the RTC application,
    \item embedded deployment within a monitored communication platform.
\end{itemize}

This separation improves modularity, scalability, and maintainability. It also allows the deepfake detector to be updated independently of the RTC transmission pipeline.

\subsubsection{Stream Ingestion and Buffer Manager}

Because RTC systems operate on continuous audio streams, the detection service processes audio in short overlapping windows rather than waiting for an entire conversation to complete. Let the incoming reconstructed stream be segmented into windows of length \(L\) with overlap \(O\).

The streaming input can be written as
\begin{equation}
X = \{x_1, x_2, \ldots, x_T\},
\end{equation}
where each \(x_t\) represents a short audio chunk extracted from \(x_{out}[n]\).

The chunking strategy serves two purposes:
\begin{itemize}
    \item It reduces inference latency by enabling online processing,
    \item It preserves local temporal context needed for reliable spoof detection.
\end{itemize}

Overlapping windows are used to reduce instability near chunk boundaries and to ensure that short-lived artifacts are not missed due to segmentation. In practice, the detector produces one prediction per chunk, and these predictions are later aggregated into a stable decision.

\subsubsection{Audio Preprocessing Module}

Before feature extraction, each input chunk is normalized and prepared for model inference. This preprocessing stage is lightweight and deterministic so that it does not introduce unnecessary latency.

Typical preprocessing operations include:
\begin{itemize}
    \item \textbf{Resampling} to a fixed sampling rate (16KHz) to match the training data.
    \item \textbf{Amplitude Normalization} standardizes the volume levels.
    \item \textbf{Pre-emphasis} applies a first order high-pass filter to amplify high frequency components.
    \item Trimming of silence or non-speech padding to mitigate variations caused by different microphones or sender side gain control,
    \item fixed-length padding for short segments.
\end{itemize}

Pre-emphasis is critical because RTC codecs often suppress high frequencies yet these bands often contain the subtle spectral cues left by synthetic vocoders. 

The result is a standardized audio segment suitable for feature extraction:
\begin{equation}
\tilde{x}_t = P(x_t),
\end{equation}
where \(P(\cdot)\) denotes the preprocessing function and \(\tilde{x}_t\) is the normalized input chunk.

\subsubsection{Feature Extraction Pipeline}

The feature extraction stage converts the preprocessed waveform into representations that expose differences between real and synthetic speech. In the proposed framework, the system extracts two complementary views of audio simultaneously.

Let
\begin{equation}
z_t = F(\tilde{x}_t),
\end{equation}
where \(F(\cdot)\) denotes the feature extraction function and \(z_t\) is the resulting feature embedding.

The feature extraction module includes the following components:

\begin{itemize}

    \item \textbf{Hand-Crafted Acoustic Features:}
    Traditional acoustic descriptors are extracted to capture low-level spectral and temporal characteristics of speech. These features include Mel-Frequency Cepstral Coefficients (MFCCs), spectral centroid, spectral bandwidth, zero-crossing rate, short-time energy, and pitch-related descriptors. Such features provide information about frequency distribution, voice quality, and temporal variations that may reveal artifacts introduced by speech synthesis and vocoding systems.

    \item \textbf{Self-Supervised Speech Embeddings:}
    High-level contextual speech representations are extracted using pretrained self-supervised learning (SSL) models such as WavLM, or Wav2Vec~2.0. These models generate rich embeddings that capture long-range acoustic and linguistic information while remaining robust to noise, codec compression, and transmission distortions commonly observed in RTC environments.

    \item \textbf{Frame-Level Acoustic Representations:}
    The continuous speech signal is segmented into short analysis frames, and frame-level embeddings are generated for each segment. These representations preserve local spectral dynamics, temporal transitions, and fine-grained acoustic patterns that may contain artifacts associated with synthetic speech generation.

    \item \textbf{Phoneme-Aligned Feature Aggregation:}
    To improve linguistic consistency modeling, frame-level features are aggregated according to estimated phoneme boundaries. This process groups acoustically related frames into linguistically meaningful units, enabling the system to capture inconsistencies between phonetic content and acoustic realization that are often observed in deepfake speech.

\end{itemize}

By combining hand-crafted acoustic descriptors with self-supervised contextual representations, the proposed framework captures complementary information from both low-level signal characteristics and high-level speech structure.

Self-supervised embeddings are particularly useful because they capture high-level speech structure and remain relatively robust under codec compression, packet loss, and receiver-side enhancement. Phoneme-aligned aggregation further reduces sensitivity to frame-level noise by summarizing features over more stable linguistic units.

The detector is not relying solely on raw waveform patterns; it operates on representations that retain both acoustic detail and contextual speech information.

\subsubsection{Classification Model Design}

The classification module is responsible for determining whether a reconstructed RTC audio segment corresponds to real human speech or AI-generated synthetic speech. To evaluate both detection performance and real-time deployment feasibility, two complementary families of classification approaches are employed: deep learning architectures that operate directly on waveform or spectrogram representations, and classical machine learning classifiers that operate on extracted feature vectors.

For each incoming audio chunk $x_t$, a feature representation $z_t$ is first extracted through the feature extraction pipeline (classical classifiers) or the raw chunk itself is used directly (deep learning classifiers). The resulting representation is then forwarded to a classification model that estimates the probability that the observed speech segment is spoofed.

The classification process is defined as
\begin{equation}
s_t = \mathcal{C}(z_t),
\end{equation}
where $z_t$ denotes the extracted feature representation, $\mathcal{C}(\cdot)$ represents the classifier, and $s_t \in [0,1]$ is the spoofing probability assigned to audio chunk $t$.

\textbf{Deep Learning Classification}

Four deep learning architectures are employed as candidate classifiers, spanning an established raw-waveform baseline, the graph-attention design adopted as the primary detector, a modernized lightweight backbone, and a spectrogram-domain variant of the graph-attention design.

\textbf{RawNet2} \cite{Tak2021_rawnet2} is an established end-to-end raw-waveform baseline in the ASVspoof anti-spoofing literature, combining a SincNet-style front end with the residual-and-recurrent backbone of the original RawNet architecture. The first layer is a SincConv layer: a bank of parameterized, band-pass Sinc filters with a fixed kernel length of 129 samples, whose cutoff frequencies are learned directly from data rather than through generic convolutional kernels. The resulting representation is max-pooled and passed through six residual blocks, each applying batch normalization, a leaky ReLU activation, and convolution, followed by Filter-wise Feature Map Scaling (FMS): a sigmoid-gated attention mechanism that rescales each channel's feature map to emphasize the most discriminative filters. The output of the residual stack is aggregated over time by a single-layer Gated Recurrent Unit (GRU) with 1024 hidden units, producing a 1024-dimensional utterance embedding, which is passed through a fully-connected layer and a final two-class output layer. Figure~\ref{fig:rawnet2_arch} illustrates this pipeline. RawNet2 provides a reference point against which the graph-attention architectures below are compared, since it represents an earlier design stage in the same architectural lineage that AASIST later extends.

\textbf{AASIST} \cite{Jung2022_aasist} (Audio Anti-Spoofing using Integrated Spectro-Temporal Graph Attention Networks) serves as the primary deep learning detector in the proposed framework. It reuses a RawNet2-style encoder (a SincConv front end followed by residual blocks) to obtain a high-level spectro-temporal feature map, but replaces RawNet2's GRU-based temporal aggregation with a graph-attention backbone that models spectral and temporal relationships jointly rather than separately. The encoder output is used to construct a spectral graph and a temporal graph, each processed independently by a Max Graph Operation (MGO): two parallel Heterogeneous Stacking Graph Attention Layers (HS-GAL) followed by graph pooling, combined element-wise by a max operation analogous to a max-feature-map non-linearity. The resulting spectral and temporal graphs are then fused by a further HS-GAL layer, which introduces a heterogeneity-aware attention mechanism together with an additional stack node that explicitly models the relationship between the two domains, followed by two more rounds of HS-GAL and graph pooling. A readout operation concatenates the node-wise maximum and average representations together with the stack node, and the result is passed to a fully-connected output layer that produces the final spoofing score. Figure~\ref{fig:aasist_arch} illustrates this pipeline. AASIST is selected as the primary detector because it reports state-of-the-art performance on ASVspoof benchmarks while remaining relatively compact, and its explicit modeling of both spectral and temporal artifact structure is well matched to the codec- and packet-loss-induced distortions this project ultimately targets.

\textbf{NeXt-TDNN} \cite{Heo2024_nexttdnn}, originally proposed for speaker verification, is repurposed here as a lighter-weight time-delay architecture. It follows the overall Time-Delay Neural Network (TDNN) design established by ECAPA-TDNN, but replaces the Squeeze-Excitation Res2Net (SE-Res2Net) block used in that architecture with a Two-Step ConvNeXt (TS-ConvNeXt) block, following the design philosophy of ConvNeXt in computer vision. Each TS-ConvNeXt block separates inter-frame and intra-frame modeling into two sub-modules: a Multi-Scale Convolution (MSC) module, which applies parallel depthwise 1-D convolutions at different kernel scales to capture inter-frame temporal context, and a frame-wise Feed-Forward Network (FFN) that models intra-frame, channel-wise context and applies Global Response Normalization (GRN) in place of the squeeze-excitation gating used in ECAPA-TDNN. A stack of these blocks is followed by multi-layer feature aggregation and attentive statistics pooling, mirroring the standard TDNN speaker-embedding pipeline. Since the original architecture is designed for speaker verification, its speaker-embedding output head is replaced here with a two-class detection head that scores each segment as bonafide or spoofed. Figure~\ref{fig:nexttdnn_arch} illustrates this pipeline. NeXt-TDNN is included as a lighter-weight architecture relative to RawNet2 and AASIST, providing a comparison point on the accuracy/efficiency trade-off relevant to real-time deployment.

In this project, the original speaker-embedding output is replaced with a two-class detection head.

\textbf{Spectro-AASIST} adapts the AASIST \cite{Jung2022_aasist} graph-attention design to operate on spectrogram (time-frequency) input rather than the raw waveform used by the original AASIST front end. The RawNet2-style raw-waveform encoder is replaced with a spectrogram extraction stage (short-time Fourier transform or mel-spectrogram) followed by a convolutional front end that produces a feature map of comparable shape to AASIST's encoder output; the spectral graph module, temporal graph module, HS-GAL fusion, and readout stages that follow are otherwise identical to AASIST (Figure~\ref{fig:aasist_arch}). This variant evaluates whether a spectrogram-domain front end, which discards the fine-grained phase and sample-level detail available to a raw-waveform encoder but is more directly comparable to the acoustic feature representations used by the classical classifiers below, changes detection performance or robustness relative to AASIST's raw-waveform variant under an otherwise identical graph-attention backbone.

Given an input representation $x_t$ (raw waveform for AASIST, RawNet2, and NeXt-TDNN, or a spectrogram for Spectro-AASIST), each deep learning model directly extracts discriminative spoofing representations and produces a spoofing score
\begin{equation}
s_t^{DL} = \mathcal{A}(x_t),
\end{equation}
where $\mathcal{A}(\cdot)$ denotes the deep learning network in question. All four models learn artifacts introduced by Text-to-Speech (TTS), Voice Conversion (VC), and other speech synthesis techniques, making them effective for audio deepfake detection: AASIST's graph attention and RawNet2's residual-recurrent backbone target these artifacts directly in the waveform domain, while NeXt-TDNN's multi-scale convolutions and Spectro-AASIST's spectrogram front end offer complementary inductive biases. Due to its state-of-the-art performance on ASVspoof benchmarks and relatively compact architecture, AASIST is selected as the primary detector for evaluating robustness under RTC-induced degradations such as codec compression, packet loss, jitter buffering, and packet loss concealment, with the remaining three architectures providing comparison points along the accuracy/efficiency spectrum.

\textbf{Classical Machine Learning Classification}

Four classical classifiers are employed as computationally efficient baselines: \textbf{XGBoost} \cite{Chen2016_xgboost}, \textbf{Random Forest} \cite{Breiman2001_rf}, \textbf{Support Vector Machine (SVM)} \cite{Cortes1995_svm}, and histogram-based \textbf{Gradient Boosting (GBM)} \cite{Ke2017_lightgbm, Friedman2001_gb}, implemented using scikit-learn \cite{Pedregosa2011_sklearn}. Unlike the deep learning models, which operate directly on waveform or spectrogram representations, the classical classifiers utilize handcrafted acoustic features and/or self-supervised embeddings extracted from reconstructed RTC audio streams.

\textbf{XGBoost} \cite{Chen2016_xgboost} (Extreme Gradient Boosting) builds an additive ensemble of shallow decision trees in a stage-wise manner: each new tree is fit to the negative gradient of the loss function with respect to the current ensemble's predictions, and its contribution is scaled by a learning rate before being added to the ensemble. XGBoost regularizes tree complexity directly in its objective function, via L1 and L2 penalties on leaf weights and a penalty on the number of leaves, which controls overfitting more explicitly than classical gradient boosting implementations. Its ensemble-of-trees decision function makes each prediction attributable to a small number of interpretable feature splits, in contrast to the distributed representations learned by the deep learning models above.

\textbf{Random Forest} \cite{Breiman2001_rf} instead builds an ensemble of decision trees independently and in parallel: each tree is trained on a bootstrap-resampled subset of the training utterances and restricted to a random subset of features at each split (bagging). Predictions are combined by averaging across all trees, which reduces the variance of the individual, typically deep and unregularized, trees without materially increasing bias. Because each tree sees a different random subset of both utterances and features, Random Forest is naturally more tolerant of a weak or partially redundant feature block than boosting-based methods, a property already observed in this project's own ablations.

\textbf{Support Vector Machine (SVM)} \cite{Cortes1995_svm} takes a different approach, learning a maximum-margin decision boundary between the bonafide and spoof classes rather than an ensemble of trees. With a radial basis function (RBF) kernel, the decision boundary is computed implicitly in a high-dimensional feature space without explicitly constructing that space, allowing SVM to model non-linear decision boundaries using only the training samples closest to the margin (the support vectors). Since the standard SVM formulation produces an uncalibrated decision score rather than a probability, probability calibration is applied so that a comparable Equal Error Rate can be computed against the other classifiers.

\textbf{Gradient Boosting (GBM)}, implemented via scikit-learn's histogram-based \texttt{HistGradientBoostingClassifier} \cite{Pedregosa2011_sklearn, Ke2017_lightgbm} rather than the classical \texttt{GradientBoostingClassifier} \cite{Friedman2001_gb}, follows the same stage-wise additive boosting principle as XGBoost, but bins continuous feature values into a fixed number of histogram buckets before searching for tree splits. This trades a small amount of split precision for a substantial reduction in training time on high-dimensional embedding features, following the histogram-based strategy popularized by LightGBM \cite{Ke2017_lightgbm}.

For each audio chunk, feature vectors consisting of Mel-Frequency Cepstral Coefficients (MFCCs), spectral statistics, energy-related descriptors, and other acoustic characteristics, or pretrained self-supervised embeddings, are extracted and represented as
\begin{equation}
z_t = [f_1,f_2,\ldots,f_n].
\end{equation}
The feature vector is then provided to the classical classifier in question:
\begin{equation}
s_t^{ML} = \mathcal{X}(z_t),
\end{equation}
where $\mathcal{X}(\cdot)$ denotes the trained classical model (XGBoost, Random Forest, SVM, or GBM). These classical models are included because previous studies have demonstrated that tree-based and margin-based classifiers can achieve strong detection performance while maintaining extremely low inference latency and greater interpretability than end-to-end deep networks \cite{Bird2023}. Consequently, they provide an effective benchmark for assessing the trade-off between detection accuracy and real-time computational efficiency.

\subsubsection{Temporal Aggregation and Decision Stabilization}

Since inference is performed on successive streaming chunks, individual predictions may fluctuate due to short-term artifacts, transient packet loss, or local noise variation. To improve decision stability, the proposed system applies temporal aggregation over a sliding window of recent predictions.

Let the set of recent spoofing scores be
\begin{equation}
S_t = \{s_{t-k+1}, s_{t-k+2}, \ldots, s_t\},
\end{equation}
where \(k\) is the aggregation window size.

A smoothed score can be computed as
\begin{equation}
\bar{s}_t = A(S_t),
\end{equation}
where $A(\cdot)$ denotes the aggregation function. In implementation, this may be a moving average, weighted average, or majority-based smoothing rule.

The final decision is then obtained from the aggregated score:
\begin{equation}
\hat{d}_t =
\begin{cases}
1, & \bar{s}_t \geq \tau \\
0, & \bar{s}_t < \tau
\end{cases}
\end{equation}

This stabilization step reduces false alarms caused by isolated distortions and produces a more reliable real-time output for the RTC application.

\subsubsection{Output Interface and Response Format}

The detection service returns a structured output to the RTC system through the same API channel used for audio ingestion. The response contains both a continuous risk score and a discrete decision label.

A typical output contains:
\begin{itemize}
    \item spoofing probability score \(s_t\),
    \item binary class label \(\hat{d}_t\),
    \item optional confidence value,
    \item optional timestamp or chunk identifier.
\end{itemize}

The output can therefore be represented as
\begin{equation}
R_t = \{s_t, \hat{d}_t, \text{timestamp}_t\}.
\end{equation}

This response enables real-time actions such as UI alerts, call monitoring warnings, logging for security analysis, and policy-based intervention by the RTC platform.
