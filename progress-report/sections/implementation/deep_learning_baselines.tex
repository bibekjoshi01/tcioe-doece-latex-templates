\subsection{Deep Learning Baseline Implementation}

Four detector architectures have been implemented and trained on the ASVspoof5 partitions described in Section~5.1, in order to evaluate both detection performance and the accuracy/efficiency trade-off relevant to the real-time deployment goal of this project. The four span a range of established design families in the anti-spoofing literature: an end-to-end raw-waveform residual-recurrent network, a graph-attention spectro-temporal network, a modernized time-delay architecture, and a spectrogram-domain variant of the graph-attention design.

\subsubsection{Models Trained}

Four deep learning architectures were implemented and trained: \textbf{RawNet2} \cite{Tak2021_rawnet2}, \textbf{AASIST} \cite{Jung2022_aasist}, \textbf{NeXt-TDNN} \cite{Heo2024_nexttdnn}, and \textbf{Spectro-AASIST}. Their architectures, and the rationale for including each, are already described in Section~4.5.5, which also provides architecture diagrams for RawNet2, AASIST, and NeXt-TDNN; Spectro-AASIST shares AASIST's graph-attention backbone (Figure~\ref{fig:aasist_arch}) with a spectrogram front end in place of the raw-waveform encoder. This subsection covers only the implementation- and training-level detail not already covered there.

As an implementation detail specific to the RawNet2 and AASIST/Spectro-AASIST reproduction, the SincConv filterbank is computed once at model initialization and registered as a fixed buffer, rather than recomputed on every forward pass; this is a computational efficiency change with no effect on the model's behavior or outputs.

AASIST, cited in Section~4.5.5 as the primary detector design on the strength of its reported ASVspoof 2019 LA performance (0.83\% EER, 0.0275 minimum t-DCF \cite{Jung2022_aasist}), has been trained directly on ASVspoof5 in this phase so that this reported performance can be independently verified on the project's own data pipeline before RTC-aware training is introduced; the corresponding ASVspoof5 figures are the clean-audio baseline results reported in the following section.

All four models are trained on clean ASVspoof5 audio, without the RTC-aware augmentation pipeline described in Section~4.8.1 applied at this stage; integration of RTC-aware training for all four architectures is planned for the final implementation phase.

\subsubsection{Audio Windowing}

Unlike the fixed-duration input used in the original recipes, obtained via repeat-padding or truncation to 64,000 samples (4.0 seconds) for RawNet2 and to 64,600 samples (approximately 4.04 seconds) for AASIST and Spectro-AASIST, and the short random crops typically used to train NeXt-TDNN-style backbones for speaker verification, all four architectures in this project are trained and evaluated on the full-length audio of each ASVspoof5 utterance, without cropping or padding to a fixed duration. Since utterance length varies across the dataset, each training batch is zero-padded to the length of its longest member rather than to a fixed global duration; both the recurrent aggregation stage in RawNet2 and the graph-attention stage in AASIST and Spectro-AASIST operate on the resulting variable-length sequence, with padded positions excluded from temporal pooling. This choice trades the fixed-size batching efficiency of the original recipes for training directly on the same duration distribution present in the evaluation protocol, avoiding any discrepancy between training-time and inference-time input statistics that a fixed crop length would introduce.

The optimizer is AdamW \cite{Loshchilov2019_adamw}, the decoupled-weight-decay variant of Adam \cite{Kingma2015_adam}, used in place of the plain Adam optimizer reported in the original RawNet2 and AASIST recipes; batch size (32) and the total training budget (100 epochs) are applied identically across all four models to keep the training budget comparable across architectures. Where a hyperparameter is not fixed by the values above, it is adopted from the corresponding architecture's original paper: a learning rate of $1\times10^{-4}$ with a weight decay coefficient of $1\times10^{-4}$, following the configuration reported for RawNet2 \cite{Tak2021_rawnet2} and carried over for AASIST and Spectro-AASIST \cite{Jung2022_aasist}, which additionally use a cosine-annealed learning rate schedule over the course of training, as reported in the original AASIST recipe (implemented in PyTorch~1.6.0+). Checkpoint selection across training epochs is described in Section~5.3.5.

\subsubsection{Class-Imbalance Handling}

Consistent with the class imbalance already noted for the ASVspoof5 splits and addressed for the classical baselines via sample and class weighting, the loss function for each deep learning model follows its own original paper rather than a single scheme applied uniformly. RawNet2 is trained with a Weighted Cross-Entropy (WCE) loss, using class weights of 1.0 (bonafide) and 9.0 (spoof), following the original recipe \cite{Tak2021_rawnet2}; this up-weights the minority bonafide class in proportion to its lower representation in the training partition. AASIST and Spectro-AASIST instead use a standard, unweighted cross-entropy loss, following the original AASIST recipe \cite{Jung2022_aasist}, which reports competitive performance without explicit class weighting. NeXt-TDNN has no published spoof-detection loss configuration to defer to \cite{Heo2024_nexttdnn}; in the absence of one, it adopts the same weighted cross-entropy scheme as RawNet2 (weights 1.0:9.0) as a reasonable default. This per-architecture asymmetry is retained deliberately rather than harmonized, consistent with this project's broader approach of adopting each baseline's own reported configuration wherever one exists.

\subsubsection{Evaluation Protocol}

Unlike the classical baselines, which are fit once per configuration, each deep learning model is trained iteratively over 100 epochs, so an additional checkpoint-selection step is required before comparison: for each architecture, the epoch checkpoint with the lowest development-set EER is selected, rather than the final epoch's weights, and only that checkpoint is carried forward for evaluation.

All four models are then compared and tuned exclusively on the development set, using Equal Error Rate (EER) as the primary metric, with precision, recall, F1-score, and ROC-AUC reported as supporting metrics. The evaluation set is held out throughout architecture, hyperparameter, and checkpoint selection, and is evaluated only once, using each architecture's selected checkpoint, after every training decision has already been finalized on the development set, to avoid evaluation-set leakage into model selection.
